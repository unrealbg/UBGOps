# Live host monitoring

Goal 03A samples a connected Linux host through the existing verified SSH transport. It installs no agent and exposes no generic command API. The operation allowlist contains fixed reads for `/proc/stat`, `/proc/meminfo`, `/proc/net/dev`, `/proc/diskstats`, bounded `/sys/class/block/*` device metadata, and the existing `LC_ALL=C df -Pk /` root-filesystem probe. Remote output is bounded to 64 KiB per command, parsed as untrusted data, and never written to application or audit logs.

## Sampling and derivation

Overview and the Combined SSH workspace's compact strip use the same useHostMonitoring hook. A visible, connected presentation requests one sample on entry and then five seconds after each request completes. Startup is deferred past discarded StrictMode setup. This completion-based timer prevents overlapping request storms when a host is slow. Polling stops when the owning view is hidden, the host disconnects, its identity changes or the component unmounts. Rust serializes observations per host; there is no independent background monitor.

The shell makes Overview and Combined mutually exclusive and exposes at most one visible compact strip for the selected host. The hook shares only an already in-flight promise for an exact HostId + HostSessionId across presentations, so moving from Overview to Combined cannot issue a second observation while the first is pending. That transient entry is removed on completion, including rejection; it stores no shared history, schedules no work and persists nothing. An already-issued native request may finish after hide; retired consumers discard its response and schedule no follow-up. Each mounted consumer retains only its own bounded history. The compact strip shows CPU, RAM, root usage and RX/TX, preserves valid zero values, and distinguishes warm-up, unavailable, stale and disconnected states. Hiding the strip does not leave a sampling or freshness timer running. Synthetic tests cover delayed completions, StrictMode, cross-presentation request sharing, zero/missing/error states, owner replacement and cleanup; new native runtime acceptance is **NOT RUN**.

The aggregate `cpu ` row from `/proc/stat` supplies CPU counters. UBGOps sums `user`, `nice`, `system`, `idle`, `iowait`, `irq`, `softirq`, and `steal`; Linux already includes guest time in user/nice, so `guest` and `guest_nice` are validated but not added again. Between two observations, utilization is `(total delta - idle delta) / total delta * 100`, where idle includes `idle + iowait`. A first observation, zero total delta, changed field shape, decrease, or overflow resets the baseline and returns no percentage.

RAM continues to use `MemAvailable`, with the documented older-kernel approximation from free, buffers, cache, reclaimable slab, and shared memory. Swap requires distinct `SwapTotal` and `SwapFree` fields; a real zero total means “Not configured.” Root-disk values reuse the bounded POSIX `df` parser.

Network sampling parses at most 128 unique interface rows from `/proc/net/dev`. Names are at most 64 bytes and cannot contain whitespace or control characters. Each row must contain exactly the 16 Linux counters. Aggregate RX/TX excludes `lo` and uses checked sums. Rates divide checked byte deltas by the exact probe-to-probe monotonic `Instant` interval measured around the `/proc/net/dev` command. If either probe timestamp is missing, mixed, zero, or non-monotonic, the calculation does **not** fall back to an unrelated sample-completion interval and resets cleanly instead. SSH transport/round-trip latency variation affects sequential probe timing; rates therefore represent average throughput between consecutive completed probe observations on the remote host rather than hardware interrupt timestamps.

Disk I/O sampling pairs fixed reads of `/proc/diskstats` (accepting standard kernel 14-, 18-, or 20-field rows where read/written sector fields are measured in 512-byte sectors) with a bounded 13-column `/sys/class/block/*` sysfs metadata probe (`dev`, `size`, `partition`, `dm/name`, `md`, `holders`, symlink target, vendor, model, `diskseq`, and `dm/uuid`/`device/wwid`/`device/serial`, excluding `loop*`/`ram*`/`zram*`/`sr*`/`fd*`). It requires matching `(major, minor)` identities across procfs and sysfs and resets baselines whenever `name`, `major`, `minor`, `kind`, `size`, `diskseq`, `device_id`, `sysfs_path`, or root-backing attribution changes. On Linux kernels >= 5.15 exposing `/sys/class/block/*/diskseq` (and/or sysfs WWID/serial/DM-UUID), device replacement even with reused names and `major:minor` pairs triggers a baseline reset; on older kernels `< 5.15` lacking `diskseq` and hardware IDs, reused name + `major:minor` + identical size/sysfs path cannot reliably distinguish replacement and resets rely on counter decrease. Classification distinguishes `VirtualDisk` (known hypervisor/virtio/vmbus/xen/cloud signals), `Partition`, `DeviceMapper`, and `MdRaid`, and stays `Unknown` conservatively for uncertain devices (never inferring bare-metal `PhysicalDisk` solely from a PCI sysfs path). One primary device is selected via `df -Pk /` (`isRootBacking: true`); when `/` is non-block (e.g., `overlay` or `/dev/root`) and only one unambiguous leaf non-partition device exists, it is surfaced explicitly as a single-device fallback (`isRootBacking: false`) without claiming it backs `/`. Multi-disk ambiguous mappings, missing metadata, or invalid monotonic intervals fail closed cleanly without affecting other metrics.

Individual parser or command failures become metric-specific warnings. A failed network read does not hide valid memory data. A transport/session failure rejects the observation. Missing values remain unavailable; valid zero rates remain zero.

## Session and frontend lifecycle

Every request and response carries exact `HostId + HostSessionId` ownership. Core captures the connection generation before remote work and revalidates generation, cancellation, connection state, and session identity before it commits a baseline. Disconnect, reconnect, host edit, delete, remote closure, and shutdown invalidate baselines. CPU and network deltas are never calculated across SSH sessions or hosts.

The renderer checks the returned ownership again. It ignores late completions after cleanup and filters displayed samples by current host/session identity. A reconnect starts an empty chart. Each chart retains at most 120 samples, approximately ten minutes at the default cadence, in component-local memory. No samples or histories are stored in SQLite, localStorage, sessionStorage, IndexedDB, Zustand, audit records, or application logs.

Freshness uses the sample UTC timestamp. The UI shows warming until the first response, marks a sample stale after 15 seconds, and distinguishes disconnected, unavailable, warming, valid zero, and no configured swap. SVG charts keep gaps for missing values and are decorative; current textual values remain accessible.

## Limits

Monitoring currently supports Linux hosts exposing the expected procfs records and a POSIX-compatible `df -P`. It monitors aggregate CPU, RAM, swap, the root filesystem, and aggregate non-loopback network bytes only. It does not inspect payloads, sockets, processes, services, containers, logs, other mounts, or persistent telemetry, and it does not alert.

## Native Windows acceptance

Native Windows acceptance passed on a production Tauri executable built from source-reviewed HEAD `ab02ecc649d3774fd1d29d5d298188678d17456c`. The [PR #4 acceptance evidence](https://github.com/unrealbg/UBGOps/pull/4#issuecomment-5844628069) records automatic monitoring, first-sample warm-up, subsequent CPU/network values, plausible memory/swap/root-disk values, valid `0 B/s`, responsive Terminal and Files workspaces, disconnect/reconnect and remote-closure behavior, and an 11-minute-plus soak. The 120-sample history cap is covered by a deterministic component regression.

Multi-host isolation and forced sampling delays longer than 15 seconds were **NOT EXECUTED** in native Windows acceptance because the environment lacked a second safe Linux host and a safe deterministic delay mechanism.
