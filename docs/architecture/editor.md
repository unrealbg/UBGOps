# Goal 02C remote text editor

The Files workspace exposes **Edit** for one selected regular remote entry. Rust opens the exact path over the current `HostId` / `HostSessionId` / `SftpSessionId` SFTP v3 session. `LSTAT` and handle `FSTAT` must identify a regular, non-symlink file with size, mtime, raw POSIX mode, uid and gid. Reads are capped at 1 MiB plus one byte, irrespective of the server's declared size. A changed file during the read is rejected. There is no generic byte-read or arbitrary remote command IPC.

Only strict UTF-8 without NUL is accepted. A UTF-8 BOM is recorded separately. Uniform LF and CRLF are normalized to LF for the textarea and encoded back to their original convention for saving. A final newline is preserved; a file without one stays without one. Lone CR and mixed newline styles are rejected. Content is rendered as text; control and bidirectional characters in displayed paths are escaped. The text buffer lives only in component-local memory. It is never placed in Query, Zustand, browser storage, audit or logs.

Opening records an immutable server-held document authority scoped to the three session IDs and exact path. It includes existing `EntryIdentity` semantics (kind, size, mtime), raw mode, uid/gid and a SHA-256 digest of the bounded original bytes. The digest catches same-size changes within SFTP v3's one-second mtime resolution. It is not a server-provided atomic compare-and-swap token. A document token expires after one hour. Save planning reserves it for one in-flight request and then one pending approval; another request for that document is rejected. A successful discard of the still-pending plan releases that reservation without changing the original revision, digest or expiry. The next review rechecks the same original bytes and metadata, so an intervening remote change produces Conflict rather than silently accepting a new baseline. Plan execution permanently consumes the document; successful or ambiguous transfer results still require Reload before another save. Clean/confirmed dirty Close and successful Reload explicitly retire the token; ignored or delayed opens retire their returned token under its original session. Document and plan expiry tasks remain bounded fallbacks.

Save planning rechecks metadata and original bytes, validates the new encoded byte limit and creates a five-minute, in-memory, one-shot `FilePlanStore` plan. It binds the current session, exact path, original revision/digest and bounded new bytes. The renderer receives only plan metadata for review. Cancel/X/Escape discard the exact plan, keep the dirty buffer, and enable a new review only after the backend confirms that the pending plan was removed and the document reservation was released. A missing, expired, already consumed or revoked plan does not confirm release. Close, expiry and session revoke remove authority, including a pending plan; a delayed planning or discard response cannot restore it. Execution consumes the plan once and enqueues a job in the existing `TransferManager` so disconnect, reconnect, host deletion and shutdown use its SF-12 quiescence and cleanup barrier. SF-13's per-host lifecycle gate serializes planning against teardown.

The job rechecks the original, creates an exclusive same-directory `.ubgops-<uuid>.edit.part`, and trusts ownership only after a successful exclusive `OPEN` reply. It streams the approved bytes using the existing bounded upload path, fsyncs when `fsync@openssh.com` v1 was negotiated, and closes the handle. A refused or lost create reply never triggers removal. A known-owned failure removes only the exact staging path, and disconnect waits for this cleanup. After staging, metadata and content are checked again; immediately before `posix-rename@openssh.com` v1, they are checked once more while cancellation is still allowed. `Finalizing` begins only after that last full read and immediately before replacement. The original is never deleted first. A lost replacement reply is `OutcomeUnknown`, with no automatic replay. A confirmed replacement remains confirmed even if cancellation arrives after Finalizing.

The staging file starts with restrictive mode 0600. Before replacement, Rust applies the original POSIX permission bits (including special bits where the server allows them), attempts uid/gid preservation if they differ, and reads back mode and uid/gid. Failure or mismatch aborts and cleans owned staging. A nonprivileged server/account that cannot preserve required ownership fails closed. The OpenSSH interoperability test verifies ordinary mode 0644 survives a save. SFTP v3 does not expose ACLs, xattrs, SELinux labels, capabilities, hard-link count/identity or other filesystem-specific metadata; replacing a file may alter those. Users should not use this editor for files whose correctness depends on them. Metadata/digest revalidation followed by POSIX rename cannot prevent every concurrent remote writer between the final check and rename.

Disconnect or session replacement revokes pending document and plan authority. Closing or unmounting the editor retires in-flight requests; a delayed plan is discarded under its original session. An approval is published only if its captured text and buffer generation still match the visible editor text. Unsaved component-local text remains visible with save disabled until explicit Reload remote; conflicts behave the same way. Reload confirms before discarding dirty text. The UI marks successful saves clean only after the transfer reports `Completed`; failed, cancelled and ambiguous outcomes retain the local text and require reload. Physical `KeyS` with Ctrl handles save from anywhere inside the active editor; Alt, Meta, AltGraph and repeat pass through.

## Milestone 02B.1 read-only Monaco viewer

The Files workspace also provides a non-mutating **View (Read-only)** action alongside the existing reviewed **Edit** flow. It calls a dedicated `open_remote_readonly_document` / `cancel_remote_readonly_open` SFTP v3 boundary backed by a supervised lifecycle (`ReadOnlyOpenSupervisor`): each admitted operation holds one of `8` global `OwnedSemaphorePermit` slots (keyed with a unique monotonic `op_id` so reused `request_id` cleanup never removes a newer registration) from admission until protocol work and any cancellation settlement complete, never releasing capacity early to detached tasks. Inside the SFTP boundary (`read_only_file_bytes`), an in-flight `OPEN` cancelled before reply awaits its late handle up to the bounded `15s` open deadline and sends `CLOSE` within `5s` (`confirmed` cleanup on `StatusCode::Ok`); if `OPEN` or `CLOSE` settlement cannot be established within those deadlines or fails over transport, the affected SFTP channel alone is locally retired (`retire_channel()` / `is_retired()`) so no further admissions use unresolved capacity while leaving parent SSH connections and active PTYs untouched (distinguishing local transport retirement from guaranteed remote handle settlement, which SFTP v3 cannot confirm after lost replies). All regular non-symlink reads remain bounded to 1 MiB (`+1` sentinel byte), enforce strict UTF-8 and NUL absence, check pre/opened/finished `LSTAT`/`FSTAT` consistency, and never allocate `FilePlanStore` write authority or persist content/paths to logs, audit, Query caches, Zustand, or browser storage.

Syntax highlighting runs completely offline using locally bundled Monaco Monarch definitions (no language servers, remote schemas, compilers, or external network requests) covering C#, C, C++, Rust, Python, Java, JavaScript, TypeScript, Go, PHP, Bash/Shell, PowerShell, SQL, JSON, YAML, TOML, XML, HTML, CSS, Markdown, Dockerfile, INI, HCL, Systemd unit files, Nginx configuration, Apache configuration, `.env` environment files, and Plain Text, with a per-tab language-mode selector to override automatic basename/extension/path detection. Multiple documents can be opened from the Files table or the inline `+` picker up to the application-wide 8-document cap without duplicating models, and an **Editor Focus** presentation mode (`docked` vs `focus`) expands Monaco across the workspace viewport while collapsing empty transfer chrome.

Because SFTP v3 has no `O_NOFOLLOW` open flag or server-side atomic file-identity compare-and-swap token, `LSTAT` -> `OPEN` -> `FSTAT` reduces but cannot eliminate a symlink or file swap within that protocol micro-window, and strict UTF-8 plus NUL rejection does not identify every arbitrary non-text binary format. Up to 8 read-only documents may remain retained application-wide (including hidden or disconnected snapshots) using opaque `ubgops-ro://document/<id>` Monaco model URIs loaded lazily offline under the unchanged CSP and `freezePrototype: true` with a pinned Vite build transform; closing a tab or deleting a host disposes its Monaco model for resource cleanup (without claiming cryptographic JS heap erasure).

### Future detachable native window readiness (not implemented in 02B.1)

Document ownership (`ReadOnlyEditorRegistry`, bound to immutable `(HostId, HostSessionId, SftpSessionId, path)` tuples and Rust backend lifecycle gates) is separated from UI presentation (`EditorPresentationMode`: `'docked' | 'focus'` today, `'detached'` in a future milestone) so future detached native Tauri windows can render a viewer without embedding SFTP/credential/mutation logic in window chrome. Implementing `'detached'` windows later will require:

1. Passing only opaque `ReadOnlyDocumentId` / window-session handles (never host credentials, keys, raw paths, or secrets in window URLs, labels, or web storage).
2. Enforcing the application-wide `MAX_READONLY_DOCUMENTS = 8` quota and read-only enforcement consistently across all windows from Rust/main-coordinator authority.
3. Broadcasting host disconnect, session replacement, tab close, and host deletion events via scoped Tauri IPC/events so detached windows immediately mark snapshots `Offline` or dispose retired Monaco models.
4. Assigning dedicated minimal Tauri capability ACLs and unchanged strict CSP (`freezePrototype: true`, `'self'` local workers/fonts only) to secondary viewer windows with zero write/save/terminal mutation commands unless separately authorized.

## Milestone 02B.2B editable Monaco core & safe-save lifecycle (pre-cutover)

Building directly over Goal 02C's safe-save IPC (`open_remote_text_file`, `plan_remote_text_save`, `execute_file_plan`, `discard_file_plan`, `discard_remote_text_document`) and Milestone 02B.1's `ReadOnlyOpenSupervisor` on the shared per-host SFTP channel (`Option A`), Milestone 02B.2B delivers the hardened backend session fence and unified Monaco editing coordinator while preserving `<RemoteTextEditor>` as the active user-facing editor until Milestone 02B.2C:

1. **Disconnect & retirement admission fence (`ReadOnlyOpenSupervisor`)**: `open_remote_readonly_document` runs `try_admit` inside one linearizable lock sequence (`slot.data` -> `sftp_sessions` -> `read_only_ops`) with zero `.await` calls under locks, guaranteeing disconnected sessions and replaced/retired SFTP channels cannot acquire semaphore capacity even after `MAX_SEALED_SESSIONS = 1024` FIFO evictions. `open_sftp` atomically swaps `sftp_sessions`, seals and signals the replaced `SftpSessionId` via `cancel_sftp_channel()`, and quiesces old tasks without touching parent SSH sessions or PTYs; `get_session` likewise pairs `revoke_session` with `cancel_session`.
2. **Single live write authority & identity separation**: `ReadOnlyDocumentId` identifies the UI tab and opaque `ubgops-ro://document/<id>` Monaco model, while `EditorDocumentId` is acquired exclusively from `open_remote_text_file` (`openEditableDocument` / `promoteToEditable`) and is the only authority accepted by `plan_remote_text_save` and `discard_remote_text_document`. Backend `FilePlanStore::register_editor_document` and `open_remote_text_file` enforce strict single active authority per `(HostId, HostSessionId, SftpSessionId, path)` across live `EditorDocumentAuthority`, pending `EditText` plans, and active `TransferManager` editor saves (`ErrorCode::Conflict` on duplicates), while `ReadOnlyEditorRegistry` mirrors synchronous unified ownership (`ownershipRef`, `opGenByTabRef`, `reserveExternalEdit`/`commitExternalEdit`) and explicit pre-open discard on `reload()` / `reloadDocument()`.
3. **LF text codec & worker-safe Monaco editing**: `textCodec.ts` mirrors `crates/ubgops-sftp/src/editor.rs` UTF-8, NUL rejection, unpaired UTF-16 surrogate rejection, BOM (+3 bytes), and CRLF (`\r\n` expansion) byte counting across exact UTF-8 replaced selections and single/multi-cursor pastes against the `1 MiB` (`1_048_576` byte) remote save ceiling and `1.5 MiB` (`1_572_864` byte) local buffer ceiling. `MonacoViewerSurface` performs undo compaction (`4 MiB` / `500` steps) and invalid-edit revert (clearing `canRedo` on revert) via coalesced `window.setTimeout(..., 0)` bound to `(documentId, model, modelRevision)` outside `onDidChangeModelContent` to prevent worker `MirrorModel` corruption, and retains per-document runtime metadata in `monacoSetup.ts` cleaned on `disposeReadOnlyModel`.
4. **Mutually exclusive save states, 7-point post-save verification & bounded polling**: `prepareSave`, `cancelSavePreparation` (`'cancellingSave'` state), and `executeSave` (`'saving'` state) transition synchronously under monotonic `opGen` guards; equal-text edits preserve existing save plans without orphan server plans. Pre-dispatch rejections (`policy`, `filePolicy`, `sftpUnavailable`, `cancelled`) settle safely as `saveFailed`; `conflict` as `conflictDetected`; and uncertain dispatches/drops (`outcomeUnknown`, synthesized IPC `connection`, `transfer`, `persistence`, unexpected job counts, `5` consecutive poll errors, or `3` missing job polls) settle strictly as `outcomeUnknown` (`lastSaveOutcome` preserved across disconnects). On `Completed`, post-save `openText` runs a 7-point verification (mounted tab, live session, exact session tuple, exact path, newline, BOM, and `refreshed.text === snapshotText`) without ever overwriting user `draftText`, recomputing `dirty = draftText !== baselineText`.
5. **Coordinated close/delete guards & legacy mutual exclusion**: Dirty tabs, `openingForEdit`, `savePreparation`, `cancellingSave`, `saving`, and `outcomeUnknown` tabs refuse unconfirmed close (`{ confirmDiscard: true }` required ONLY for `dirty`/`outcomeUnknown`, never bypassing active async operations), register `beforeunload` protection, guard `reloadDocument` on dirty buffers (`allowDirtyDiscard`), and block host deletion via `canPurgeHost` / `getUnsavedWorkSummary`. While `<RemoteTextEditor>` remains active for 02B.2B UI editing, `FilesWorkspace` synchronizes single write authority via `reserveExternalEdit` / `commitExternalEdit` / `releaseExternalEdit`.
